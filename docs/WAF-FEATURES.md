# 3panel WAF 功能文档

> 目标：对标并超越 1Panel 商业版 WAF 与雷池（SafeLine），不是开源工具的简单封装，而是自研语义 + ML 混合检测引擎。
> 状态：实现中。P0 核心链路已具备，但性能、检出率/误报率基准和真实 3Panel OpenResty 环境验收尚未达标，不得标记为发布完成。
> 范围：仅覆盖 3Panel 管理的 OpenResty 服务，不接管或修改用户自行部署的 Nginx。

## 0. 当前实现与验证状态（2026-09-28）

已实现：站点级数据面热启停、SQLi/XSS/RCE/LFI/SSRF/危险上传检测，以及 Log4Shell、SSTI、XXE、Java/PHP 反序列化、模板/代码注入和高危暴露路径检测；全局/站点名单、TTL、allow/deny/log/challenge、CC、机器人与扫描行为检测、请求走私检测、日志检索/统计/导出/一键加白、误报标记并自动生成 24 小时站点 IP+路径组合放行规则、GeoIP 归属地、Webhook，以及规则文件原子更新。Go 控制面将无 TTL 的 exact 名单规则预编译为哈希表，Lua 请求面直接查表，其他规则保留解释执行。首次为站点安装 Lua 入口需要一次 OpenResty reload；安装完成后的日常启停只更新数据面，不 reload。前端在“网站”菜单下提供独立 WAF 入口，并保留单站点设置中的 WAF 页签。

安全与运行约束：请求阶段从共享内存读取规则；规则文件由后台定时器刷新；事件先进入共享内存队列，再由定时器批量落盘。日志来源 IP 与规则匹配统一使用经过 OpenResty `real_ip` 处理后的 `remote_addr`，不直接信任客户端传入的 `X-Forwarded-For`。包含密码、令牌、Cookie 等敏感字段的日志值整体遮蔽，超长字段截断。

当前自动验证：Go WAF service/exporter 测试、Lua 单元测试、Docker OpenResty 端到端测试。端到端测试包含无需 reload 的关闭/重新开启验证。可执行命令：

```bash
cd agent && go test ./utils/waf ./app/service -count=1
cd agent/utils/waf/lua && luajit waf_test.lua
cd agent/utils/waf && bash e2e_smoke.sh
cd agent/utils/waf && RUN_BENCHMARK=1 bash e2e_smoke.sh
# 使用已知攻击日志全量回放；可加 --deduplicate 查看去重样本检出率
python3 agent/utils/waf/replay_detect_log.py /path/to/detect_log.xlsx
```

已知攻击日志基线：`detect_log.xlsx` 共 103,179 条、56,166 个不同载荷、22,495 个不同路径。初始引擎对去重样本检出率为 12.30%；补充 P1 攻击族、SQLi 数据库指纹、折叠前路径穿越与高危备份暴露后，全量检出率为 40.32%（41,600 / 103,179），去重检出率为 46.92%（32,312 / 68,861）。继续按未命中样本补签名后（Struts2 OGNL、ThinkPHP、APISIX Lua 注入、Fastjson AutoType、Shellshock、Goby 命令探针、MySQL 版本注释与 `DBMS_PIPE` 盲注、OAST 回连、Windows 敏感路径、字面 `\n` 归一化等），去重检出率提升到 89.57%（61,682 / 68,861）。该表只有路径和攻击载荷，没有完整 Header/Cookie/Body 原文，不能把剩余未命中全部归因于检测引擎，但当前结果也明确不足以证明 `>= 99%`。回放工具支持 `--show-misses N` 输出未命中样本，用于后续分类补规则。

未命中分布（去重口径，共 7,179 条）以 SQLi（约 3,900）、RCE（约 1,520）、代码注入（约 400）为主：其中相当一部分是同一模板换随机数/路径的重复形态（如 jeecg 系未授权字典接口、cgi-bin 命令执行、OAST 换域名），另有 `phpmyadmin`、`reset-password` 一类仅凭路径无法判定攻击意图的探测。后续提升空间主要在按路径模板聚合的虚拟补丁规则，而不是继续堆叠单条 payload 特征。

未通过的发布门槛：将普通请求的候选与暴露路径检查改为 OpenResty PCRE JIT 后，本地 Docker `wrk` 多轮对照中吞吐下降由约 30% 降到约 12%~24%；短压测波动较大，只能作为优化基线，不能替代文档要求的 P99 延迟增量 `< 5%`。生产同款 `1panel/openresty:1.31.1.1-2-4-noble` 镜像已在隔离容器中通过之前的 19 项端到端测试；本轮新增的预编译规则用例在本地 OpenResty 镜像中使总数达到 20 项并全部通过，但生产同款镜像本轮拉取遇到镜像仓库单层长时间重试，新用例尚未在该镜像重跑。OWASP 检出率 `>= 99%`、误报率 `<= 0.1%`、控制面 API 到数据面的完整链路以及浏览器验证仍需完成。P1-P3 未实现项目继续以本文清单为准。

## 1. 定位与差异化

| 维度 | 1Panel 商业 WAF | 雷池 | 3panel WAF |
|---|---|---|---|
| 检测方式 | 规则为主 | 语义检测引擎 | 语义引擎 + ML 异常检测 + 规则三层 |
| 流量接入 | 站点配置绑定 | 需接管流量 | 面板即流量入口，站点一键开启 |
| L4 防护 | 无 | 弱 | 支持（TCP/非 HTTP 资产） |
| 虚拟补丁 | 无 | 部分 | 内置 CVE 规则热更新 |
| 策略运营 | 基础 | 基础 | 灰度 / 版本化 / 回滚 |

核心优势：3panel 本来就是站点反代的入口，用户无需额外部署流量接管；WAF 与站点配置天然联动。

## 2. 功能清单

### P0 —— 基础可用（第一阶段必须完成）

- **站点级 WAF 开关**：站点编辑页一键开启，自动生成/更新站点 WAF 配置
- **检测能力（语义级）**：SQL 注入、XSS、RCE、LFI/路径穿越、SSRF、文件上传攻击
- **黑名单 / 白名单（核心基础能力）**
  - 多维度匹配：IP / IP 段 / CIDR、URL 路径、User-Agent、Referer、Header、Cookie、请求方法、组合条件
  - 自定义匹配表达式（支持通配符与正则）
  - 名单作用域：全局名单、站点级名单（站点级覆盖全局）
  - 生效动作：拦截 / 放行 / 仅记录
  - 名单生效优先级：白名单 > 黑名单 > 检测引擎（命中白名单直接放行并跳过检测）
  - 临时名单：支持 TTL（如封禁 24 小时自动解除），适用于人工处置与自动封禁联动
- **拦截与放行**
  - 拦截动作：直接拒绝（4xx）、挑战验证（JS 挑战 / Cookie 验证）、重定向
  - 放行动作：直接转发、转发但记录（审计模式）
  - 按规则/规则组独立设置动作，而非全局一刀切
  - 观察模式（仅记录不拦截）：新策略上线、规则灰度时必备
- **拦截日志（事后分析）**
  - 全量记录被拦截/被放行的可疑请求：原始请求报文、命中的检测项/规则、动作、耗时、来源 IP、归属地、UA
  - 支持按站点、时间、攻击类型、来源 IP、规则 ID 多维检索
  - 单条日志支持"加入白名单"（一键生成放行规则）
  - 日志保留策略可配置，支持导出（CSV / JSON）用于外部 SIEM 分析
  - 聚合统计：攻击类型分布、Top 攻击源、时间趋势

### P1 —— 追平雷池

- 机器人识别：搜索引擎等善意 bot 白名单，扫描器/爬虫指纹拦截
- GeoIP / ASN 维度策略（封禁国家、封禁 IDC 网段）
- API 资产自动发现与参数基线，偏离基线告警
- 规则热更新：本地规则库 + 远程规则订阅源
- CC 防护：QPS 限流、慢速攻击识别、挑战降级
- 虚拟补丁：针对公开 CVE 的临时拦截规则，无需改应用代码

#### 协议覆盖（商品级底线，随 P1 完成）

- WebSocket：帧级检测升级请求头与首帧载荷，长连接内消息抽样检测
- gRPC：识别 `content-type: application/grpc`，对 protobuf 载荷按二进制启发式 + 长度分布检测（不做全量反序列化）
- HTTP/2：Nginx 原生终止 h2 后降级为 h1 进入检测流水线，对外保持 h2
- IPv6：名单/GeoIP/限流全链路支持 v6 与 v6 网段
- 大文件上传：流式抽样检测 + 上传扩展名/魔数校验，不做全量缓冲

#### 反检测对抗（差异化能力，随 P1 完成）

- HTTP 请求走私识别（CL/TE 不一致、畸形分块）
- 分块编码与多重编码混淆规范化（URL 多解、Unicode 归一、HTML 实体嵌套）
- TLS 指纹（JA3/JA4）采集与策略联动（异常指纹打标或拦截）
- 扫描器行为指纹：路径遍历探测节奏、404 率突增、多站点横向移动

#### 误报处理工作流（随 P1 完成）

- 误报上报入口：日志页一键标记误报，附带完整请求上下文自动生成工单
- 临时放行：误报处置期间对命中规则/路径组合生成 TTL 放行项，不影响整体防护
- 规则热修：管理员可临时禁用单条规则（带原因记录），远程规则更新修复后灰度恢复
- 灰度恢复流程：恢复前先对历史误报样本重放验证，确认不误杀再全量生效

#### 权限与审计（随 P1 完成）

- RBAC：WAF 管理、名单操作、日志查看分权，普通站点管理员不可修改全局名单
- 配置变更审计：名单/策略/规则的每次变更记录操作人、前后值、时间，不可删除，支持导出

#### 备份与恢复（随 P1 完成）

- WAF 配置（策略、名单、规则开关状态）纳入面板备份体系，支持按站点/全量恢复
- WAF 组件升级失败自动回滚到上一稳定版本，回滚不丢失名单与日志

### P2 —— 超越雷池

- ML 异常检测：无监督学习正常流量基线（参数基数、长度分布、UA 聚类），对异常请求打分
- L4 模式：代理保护 TCP/非 HTTP 资产
- 威胁情报联动：社区恶意 IP 黑名单订阅、封禁 IP 反哺
- 策略版本化：按站点灰度生效、版本回滚、A/B 对比

### P3 —— 运营与商业形态

- 攻击大屏 / 世界地图、周期报表
- SIEM 导出（Syslog / Webhook）
- SaaS 托管控制台：集中管理多节点 3panel（商业版形态）
- 国际化：WAF 全部 UI 文案纳入面板多语言体系
- 合规：日志脱敏策略可配置（满足个保法/GDPR 最小化要求），支持完全关闭 Cookie/Header 落库
- 容量规格书：发布单节点官方规格（保护站点数 / 峰值 QPS / 日志吞吐），按规格做发布前压测

## 3. 功能优先级结论

先打穿「L7 + 语义检测 + 站点集成 + 黑白名单 + 拦截日志」这条主线：
黑白名单、拦截/放行、日志分析是 WAF 的信任基础，必须第一版就完整；大屏、L4、SaaS 都是后续锦上添花的部分，不进入第一阶段。

## 4. 验收标准（第一阶段）

- 常见 OWASP Top 10 攻击样本集（含编码混淆绕过样本）检出率 ≥ 99%，误报率 ≤ 0.1%（对比 CRS 默认配置的基线）
- 检测开销：开启 WAF 后单站点延迟增量 < 5%
- 站点开启/关闭 WAF 无需重载其他站点
- 黑名单/白名单变更秒级生效，无需重启
